The journalist should start by doing an investigation on the latest activity and write the first article — a summary of what's happening across the project. This is something I would like to consume directly, so it should connect to my workflow.

**2. Interview the Librarian**
I'd like the journalist to interview the librarian. This needs some figuring out — you could swap roles or find a creative way to make it work. **3. Publish & Create a Runbook**
Based on the above, the journalist should create a story that gets published. The journalist should also do some thinking about *how* they publish — create a runbook or operational document explaining the publishing process. For now, outputs should be markdown files.

**4. Feature Request: Mini Website**
The journalist should create a feature request (directed at the architect and developer) for a mini website where I can easily consume published materials.

Key points on the website:
- Since this runs on GitHub Actions and is a public repo, we can set up **GitHub Pages** to publish.
- Whenever the journalist publishes material, it goes to the website.
- That website becomes the place I go to see latest updates.
- If we add automation (e.g. the journalist agent runs at regular intervals), the execution output updates the website with the latest news automatically.

**Important:** The journalist is *not* building the website. The journalist writes the feature request describing what it should look like. Then the architect maps the architecture, the developer builds it, and the QA tests it.

Eventually we'll do something similar for the librarian (the library also needs to be easy to navigate), but let's start with the news site first.
